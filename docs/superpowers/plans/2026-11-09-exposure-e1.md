# Exposure-Check E1 (Spur 1 „Lauscht“) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Neues Node64-Modul `exposure` (Phase E1): zeigt, auf welcher IP-Adresse welche Ports offen sind bzw. gehört wird: die Node selbst aus `/proc` (kein Verkehr) und bekannte Geräte der IPAM-Subnetze per TCP-Connect-Scan (opt-in).

**Architecture:** Neues Paket `internal/exposure` nach dem Muster von `internal/ipam` (eigene Tabelle, `module.Module`, Seite, lokale API). Quellen werden von `cmd/node64/main.go` per Funktionen eingespeist (lauschende Sockets, Port-Verwaltung, IPAM-Subnetze und -Hosts), das Modul kennt weder `ipam` noch `web`. Der Scanner ist eine eigenständige, injizierbare Funktion mit hartem Schutz (nur private Netze).

**Tech Stack:** Go 1.27, `internal/netstat`, `internal/ports`, `modernc.org/sqlite` über `internal/store`, `html/template` + Bootstrap 5, i18n de/en.

**Spec:** `docs/PLAN-NODE64-EXPOSURE.md` (Spur 1, Phase E1; E2 UPnP/Zusammenführung, E3 Meldungen/Dashboard, E4 Messpunkt zweite Node, E5 ipv64, E6 IPv6/UDP folgen als eigene Pläne). Projektregeln: `CLAUDE.md`. Baut auf dem Branch `ipam` auf (Verdrahtung in `main.go`, Muster).

## Global Constraints

- Neuer Branch `exposure` von `ipam` aus. Code-Kommentare deutsch **ohne Umlaute**, Dichte wie in der Umgebung; keine Umbauten außerhalb des Auftrags. `gofmt` sauber.
- Texte immer zweisprachig in `internal/i18n/locales/de.json` und `en.json`; `TestEveryKeyExistsInAllLanguages` bleibt grün.
- Modulname `exposure`, Pfad `/exposure`, Tabelle `exposure_listen`, Audit-Aktionen mit Präfix `exposure.`, Version `0.1.0`, `CHANGELOG.md` und `CHANGELOG.en.md` im Modul (Format `docs/MODUL-VERSIONEN.md`), `Order: 47` (zwischen IPAM 45 und Honeypot64 50).
- Zeiten RFC3339 UTC über `store.FormatTime`/`store.ParseTime`. `store.Writer()` hat **eine** Verbindung: in einer Transaktion nur `tx` benutzen.
- Standard **aus**. Der LAN-Scan läuft nur für Subnetze, die der Nutzer einschaltet; er prüft nur **bekannte** IPAM-Adressen (in den letzten 24 Stunden gesehen), nie ein ganzes Netz durchsuchen.
- Scan-Schutz: nur private Bereiche (10/8, 172.16/12, 192.168/16, 100.64/10, `fc00::/7`) **und Loopback** (Entscheidung des Planverfassers, für die Tests und die Node selbst); Link-Local, öffentliche und reservierte Adressen werden abgelehnt.
- Scan-Voreinstellungen: 16 parallel, 1 Sekunde je Verbindung, 200 ms Pause zwischen Geräten, höchstens 100 Ports je Lauf (Standardliste plus eigene). Intervall wählbar 1, 6, 24 oder 168 Stunden, Standard 24. Die Node selbst wird alle 5 Minuten gelesen (`selfEvery`, kein Verkehr).
- Es werden nur **offene** Ports gespeichert (Zustand `open`, später `gone`); „zu“ steht nicht in der Tabelle.
- Nichts am Portal (`deploy/`), nichts an hubs. Modul wird erst in Task 9 in `main.go` registriert.
- **Commits nur nach Freigabe durch Lucas.** Wenn freigegeben: `git add <neue Dateien>` und `git commit -m "Exposure 0.1.0: …" -- <Pfade>` (deutsch, Modul und Version vorn), nie `-a`/`-A`.
- Tests: schnell lokal mit `go test ./internal/exposure/... -run <Name> -v`; maßgeblich ist der Linux-Lauf (Docker oder Box, Task 9).

## Review Focus

Eingaben und Zustände, die die Spec nicht nennt, die aber echte Nutzer treffen (jede Zeile hat einen Test in der genannten Task):

1. Ziele, die nie gescannt werden dürfen: öffentliche Adressen (`8.8.8.8`), `169.254.x.x`, IPv6 Link-Local (`fe80::1`), Multicast, `0.0.0.0`, Adresse mit Zonenkennung (Task 3).
2. Ein Gerät, das gerade **offline** ist (alle Verbindungen laufen in den Zeitlimit): seine bisher offenen Ports dürfen **nicht** auf `gone` springen (Task 5, 6).
3. `/proc` nicht lesbar (macOS, eingeschränkte Umgebung): „unbekannt“ statt „keine Ports offen“, bestehende Zeilen bleiben (Task 4, 7).
4. Eigene Ports des Nutzers: Duplikate, `0`, `65536`, `abc`, mehr als 100 Einträge (Task 2).
5. Zwei Läufe gleichzeitig („Jetzt prüfen“ während der Schleife läuft): serialisiert, der zweite meldet „läuft schon“ statt doppelt zu scannen (Task 6).
