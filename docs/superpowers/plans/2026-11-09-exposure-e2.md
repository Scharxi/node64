# Exposure-Check E2 (Spur 2 „Erreichbar“, Indiz über UPnP) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Modul `exposure` 0.2.0: die Node fragt den Router per UPnP nach den aktiven Port-Weiterleitungen, führt sie mit der Innen-Sicht (E1) zusammen und zeigt je Weiterleitung Vertrauensstufe (wahrscheinlich/unbekannt) und Einordnung (erwartet/unerwartet/neu/weg).

**Architecture:** Neue Dateien im Paket `internal/exposure`: ein kleiner UPnP-IGD-Client mit der Standardbibliothek (SSDP, Gerätebeschreibung, SOAP) mit hartem Schutz gegen fremde Ziele, ein Speicher für Weiterleitungen und „erwartete Ports“ (Migration 0002), eine reine Funktion `Classify`, die Weiterleitungen, lauschende Ports und Erwartungen zusammenführt, und die Einbindung in Läufe, Seite und API. Alles hinter einem Schalter (Standard aus).

**Tech Stack:** Go 1.27 (nur Standardbibliothek für UPnP: `net`, `net/http`, `encoding/xml`), `modernc.org/sqlite` über `internal/store`, `html/template` + Bootstrap 5, i18n de/en.

**Spec:** `docs/PLAN-NODE64-EXPOSURE.md` (Abschnitt Spur 2, „Indiz: Router fragen (UPnP IGD)“, „Zusammenführung der Spuren“; Phase E2). E1 ist umgesetzt (`docs/superpowers/plans/2026-11-09-exposure-e1.md`). Projektregeln: `CLAUDE.md`.

## Global Constraints

- Neuer Branch `exposure-e2` von `exposure` aus. Code-Kommentare deutsch **ohne Umlaute**, Dichte wie in der Umgebung; keine Umbauten außerhalb des Auftrags. `gofmt` sauber.
- Texte zweisprachig in `de.json` und `en.json` (Block `exposure` erweitern, nicht neu anlegen); `TestEveryKeyExistsInAllLanguages` bleibt grün. Neue Audit-Aktionen `exposure.expected_add`, `exposure.expected_remove`.
- Modulversion `0.2.0`, beide Modul-Changelogs und beide Wurzel-Changelogs ergänzen (`CLAUDE.md`). Keine neuen Abhängigkeiten.
- Zeiten RFC3339 UTC über `store.FormatTime`/`store.ParseTime`. `store.Writer()` hat **eine** Verbindung: in einer Transaktion nur `tx` benutzen.
- UPnP ist **opt-in** (Standard aus, Einstellung `exposure.upnp`), weil SSDP Multicast sendet. Abfrage höchstens stündlich (`upnpEvery`, Paketvariable) und bei „Jetzt prüfen“.
- UPnP-Schutz (hart, vor jeder Anfrage): Beschreibungs-URL nur `http`/`https`, Host ein **IP-Literal** im privaten Bereich oder Loopback (`ScanAllowed`), keine Hostnamen; die Steuer-URL muss denselben Host und Port haben wie die Beschreibung. Zeitlimit je Anfrage 5 s, SSDP-Wartezeit 2 s, Antworten höchstens 1 MiB, höchstens 256 Weiterleitungen je Abfrage.
- Vertrauensstufen: nur `likely` und `unknown` (E2). `confirmed` kommt erst mit einem Außen-Messpunkt (E4). Bei IPv6 sagt UPnP nichts (Spec): kein Eintrag, die Seite erklärt es.
- Erwartungen (`exposure_expected`) gelten für Protokoll und **externen** Port, nicht je Adresse (Vereinfachung gegenüber der Spec, Entscheidung des Planverfassers).
- „Neu“ = erste Sichtung vor weniger als 24 Stunden. „Weg“ = früher offen, zuletzt vor höchstens 7 Tagen gesehen.
- Nichts am Portal (`deploy/`), nichts an hubs. **Commits nur nach Freigabe durch Lucas:** `git add <neue Dateien>` und `git commit -m "Exposure 0.2.0: …" -- <Pfade>`, nie `-a`/`-A`.
- Tests: schnell lokal mit `go test ./internal/exposure/... -run <Name> -v`; maßgeblich ist der Linux-Lauf im Docker (Task 8).

## Review Focus

Eingaben und Zustände, die die Spec nicht nennt, die aber echte Nutzer treffen (jede Zeile hat einen Test in der genannten Task):

1. **Fremde Ziele:** Eine Beschreibungs- oder Steuer-URL auf eine öffentliche Adresse, einen Hostnamen, ein anderes Schema oder einen anderen Host/Port als die Beschreibung wird abgelehnt, **ohne** dass eine Anfrage hinausgeht (Task 2).
2. **Feindlicher oder kaputter Router:** endlos weitere Weiterleitungen, Antwort über 1 MiB, hängende Verbindung: begrenzt, nach Zeitlimit beendet (Task 2).
3. **Kein UPnP / Router nicht gefunden / Fehler:** bestehende Zeilen bleiben unberührt, die Seite nennt den Grund, nichts wird als „weg“ gewertet (Task 5).
4. **Seltsame Einträge:** deaktiviert, Port 0, Protokoll weder TCP noch UDP, interne Adresse nicht lesbar, Beschreibung mit HTML oder 5000 Zeichen (Task 2, Task 6).
5. **Erfolg mit null Weiterleitungen** setzt bisher bekannte Weiterleitungen auf „weg“; ein **Fehler** tut es nie (Task 1, Task 5).

### Task 4: Zusammenführung und Einordnung (`Classify`)

**Files:**
- Create: `internal/exposure/classify.go`, `internal/exposure/classify_test.go`

**Interfaces:**
- Consumes: `External`, `Expected`, `Listen`, `SelfAddress` aus Task 1 und E1.
- Produces:
  - `type Level string` mit `LevelLikely = "likely"`, `LevelUnknown = "unknown"` (`"confirmed"` ist für E4 reserviert, noch **keine** Konstante).
  - `type Class string` mit `ClassExpected = "expected"`, `ClassUnexpected = "unexpected"`.
  - `type OverviewRow struct { Proto string; Port int; Level Level; Class Class; Device string; InternalAddr string; InternalPort int; Service string; Description string; Listening, New bool; FirstSeen, LastSeen time.Time }` (`Device`: `SelfAddress` für die Node, sonst Name aus `Names`, sonst die Adresse)
  - `type OverviewInput struct { External []External; Listen []Listen; Expected []Expected; Local []netip.Addr; Names map[string]string; Now time.Time }`
  - `func Classify(in OverviewInput) (open []OverviewRow, gone []External)`

Regeln: Das Ziel einer Weiterleitung ist die Node, wenn `InternalAddr` (entpackt) in `Local` steht, sonst das Gerät mit dieser Adresse. **Listening** = es gibt eine offene `Listen`-Zeile für (Ziel, Protokoll, interner Port); für die Node gelten die Zeilen mit `Address == SelfAddress`. **Level** = `likely`, wenn Listening, sonst `unknown`. **Class** = `expected`, wenn (Protokoll, externer Port) in `Expected` steht oder das Ziel die Node ist und die lauschende Zeile einen `Owner` hat; sonst `unexpected`. **Service** = Dienst der lauschenden Zeile, sonst `ServiceName`. **New** = `State == open` und `Now - FirstSeen < 24 h`. `open`: Zeilen mit `State == open`, sortiert nach Port, dann Protokoll. `gone`: `State == gone` und `Now - LastSeen <= 7 Tage`, sortiert nach `LastSeen` absteigend.
